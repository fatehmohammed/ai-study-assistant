Core AI Concepts to Master
Understand these deeply — they come up in every AI interview

LLM (Large Language Model)

A neural network trained on massive text data to predict the next token. Takes text in, outputs text.

Interview Answer "An LLM is a transformer-based model trained to predict tokens. It doesn't 'think' — it finds the statistically likely next word given context. Claude, GPT, and Gemini are all LLMs."

Tokens

Text broken into chunks. "learning" ≈ 1 token. Matters for cost, speed, and context window limits.

Interview Answer "Tokens are sub-word units. 1 token ≈ 0.75 words. They determine API cost, max input size, and latency. Claude's context window is measured in tokens."

Prompt Engineering

Crafting system + user messages to get reliable, high-quality outputs from an LLM.

Interview Answer "Prompt engineering involves structuring system prompts to set behavior, using few-shot examples to guide format, and chaining prompts to break complex tasks into steps."

Temperature

Controls output randomness. 0 = deterministic. 1 = creative. For factual Q&A, use 0.

Interview Answer "Temperature scales the logits before sampling. Low temperature makes the model pick the highest-probability token consistently. High temperature flattens the distribution, adding variety."

Embeddings

Converting text into a list of numbers (vector) that captures meaning. Similar text → similar vectors.

Interview Answer "Embeddings are dense vector representations where semantic similarity maps to geometric proximity. They enable search that understands meaning, not just keywords."

Vector Database

A database optimized for storing and searching embeddings. Find similar content by meaning, not exact match.

Interview Answer "Vector DBs use approximate nearest-neighbor algorithms (like HNSW) to find semantically similar documents at scale. ChromaDB, Pinecone, and Weaviate are common choices."

RAG (Retrieval-Augmented Generation)

Fetch relevant documents → inject into the prompt → LLM answers based on real data, not hallucinations.

Interview Answer "RAG addresses LLM hallucination and knowledge cutoff by retrieving relevant chunks from a vector store and grounding the model's answer in real source material."

Tool Use / Function Calling

Define functions Claude can call. The model decides when and how to invoke them during a response.

Interview Answer "Tool use lets the model emit structured JSON describing a function call. The app executes the function and feeds results back. This is how agents take actions beyond text generation."

Context Window

The maximum tokens Claude can read at once (input + output). Large PDFs must be chunked.

Interview Answer "Context window limits how much text the model can attend to. Chunking splits documents into overlapping segments so each fits within this limit while preserving continuity."

Chunking

Splitting large documents into smaller overlapping pieces so each chunk fits in the context window.

Interview Answer "Chunk size and overlap are critical RAG hyperparameters. Too small loses context; too large reduces retrieval precision. Overlap prevents answer splitting at chunk boundaries."

Cosine Similarity

Measures the angle between two embedding vectors. Score of 1 = identical meaning, 0 = unrelated.

Interview Answer "Cosine similarity ignores vector magnitude and measures directional alignment, making it robust for comparing text embeddings regardless of document length."

Agent Loop

LLM decides → calls a tool → gets result → decides again → repeat until task is done.

Interview Answer "An agent loop is a ReAct-style cycle: Reason about the goal, Act by calling a tool, Observe the result, repeat. The model orchestrates multi-step tasks autonomously."

Top Interview Questions You'll Be Able to Answer
Memorize the structure, not the words — then explain it in your own voice
Q: What is RAG and why do we need it?
RAG (Retrieval-Augmented Generation) solves two problems with LLMs: hallucination and knowledge cutoff. Instead of relying purely on what the model was trained on, you retrieve relevant documents from your own data store and inject them into the prompt as context. The model then generates an answer grounded in real source material, which you can cite and verify.
Q: How do embeddings work?
An embedding model converts text into a dense vector — a list of ~1500 numbers. The model is trained so that semantically similar text produces similar vectors. You measure similarity using cosine similarity: the angle between two vectors. If the angle is small (cosine ≈ 1), the texts are semantically close. This lets you find related content without keyword matching.
Q: What's the difference between a system prompt and a user message?
The system prompt sets the model's persona, constraints, and behavior for the entire conversation — it's like a contract. The user message is the actual input for that turn. System prompts are processed first and carry more weight in steering the model's style and restrictions.
Q: What is chunking and why does it matter in RAG?
Chunking splits large documents into smaller overlapping segments that fit within the context window. Chunk size is a critical hyperparameter: too small loses context, too large reduces retrieval precision. Overlap (e.g., 10–20% shared tokens between adjacent chunks) prevents splitting an answer across two chunks that are never retrieved together.
Q: How would you prevent hallucinations in an AI app?
Three layers: (1) RAG — ground answers in retrieved source documents; (2) Constrained prompts — instruct the model to say "I don't know" if the answer isn't in the context; (3) Source attribution — return the source chunk alongside the answer so users can verify. For high-stakes cases, add a second LLM call to fact-check the first.
Q: What is an agent and how does the loop work?
An agent is an LLM given tools and the ability to decide which to call. The loop: Reason (model decides what to do), Act (calls a tool), Observe (receives tool output), repeat until the task is complete. This is the ReAct pattern. The key risk is infinite loops — always add a max-step guard.
